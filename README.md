# E2E-тесты stage.ecom.md

Автотесты интернет-магазина на Playwright + pytest. Стенд: `https://stage.ecom.md/ru`
(базовый URL задан в `pytest.ini`).

## Развёртывание на новой машине

```bash
git clone https://github.com/maxtrit11/ecom-playwright-tests.git
cd ecom-playwright-tests

pip install -r requirements.txt
playwright install
```

**Python 3.11.** На других версиях окружение не проверялось; если в системе
несколько версий, запускать через `py -3.11 -m pytest ...`.

### Учётные данные

`tests/fixtures/users.json` содержит реальные учётки stage, поэтому он в
`.gitignore` и в репозиторий не попадает. После клонирования:

```bash
cp tests/fixtures/users.example.json tests/fixtures/users.json
# и вписать реальные значения
```

Без этого файла суита **собирается и гоняется** — тесты, которым нужен вход в
кабинет, просто скипаются с пояснением в отчёте. Так же они скипаются, если в
`users.json` остались плейсхолдеры `REPLACE_ME`.

## Запуск

```bash
pytest                                  # вся суита
pytest tests/test_search.py             # один файл
pytest -k "favorites"                   # по имени
pytest --headed                         # с видимым браузером
```

### Маркеры

| Маркер | Смысл |
| --- | --- |
| `smoke` | быстрый дымовой набор критичных проверок |
| `requires_auth` | нужен реальный вход в кабинет |
| `real_submit` | тест реально отправляет заявку/заказ на stage (создаёт лид) |

```bash
pytest -m smoke                   # только дым
pytest -m "not real_submit"       # не создавать лиды на стенде
```

Часть сценариев (сабмит предзаказа, заявка на кредит) на stage проходит только
в `--headed`: в headless анти-бот стенда режет отправку, и тесты дают ложные
падения. В CI это решается запуском headed под Xvfb.

## Структура

| Путь | Что внутри |
| --- | --- |
| `tests/` | тесты; `tests/account/` — личный кабинет |
| `tests/fixtures/` | тестовые данные, включая учётки (локально) |
| `conftest.py` | общие фикстуры: ожидание гидрации Nuxt, гашение виджетов-перехватчиков, таймауты, загрузка учёток |
| `reporting.py` | терминальная сводка, HTML-отчёт, сводка для GitHub Actions |
| `run_batches.py` | прогон файл-за-файлом с паузами — щадящий режим, чтобы stage не отвечал 502 под нагрузкой |
| `.github/workflows/` | `smoke.yml` (на push) и `e2e.yml` (ночной прогон) |

## Особенности стенда

Стенд отдаёт серверную разметку раньше, чем Vue навесит обработчики, поэтому
клики теряются, если ждать только видимости элемента. За это отвечает
`wait_hydrated` в `conftest.py` — там же расписаны замеры, на которых основано
текущее решение. Под нагрузкой stage подвисает, поэтому в `pytest.ini` включены
два перепрогона упавших тестов (`--reruns 2`), а `STAGE_SLOW=1` удваивает
таймауты.
